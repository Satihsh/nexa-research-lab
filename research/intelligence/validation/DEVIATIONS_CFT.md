# DEVIATIONS / INTERPRETATIONS: CFT (written 2026-10-17 BEFORE any data; PREREG_CFT.md d8ba8ce4)

| # | Interpretation | Why |
|---|---|---|
| I-1 | **No re-entry in the same direction at the same decision time** as an exit. A reversal (opposite direction) at that time is allowed. | Otherwise a VWAP-stop exit with price still above UB would re-buy at the same price: pointless churn the paper does not describe. |
| I-2 | **Roll days** (a mapping change is flagged at the first bar of the new day) drop the gap term: UB = O(1+σ), LB = O(1−σ). | With continuous-contract data a stale C_{t−1} from the old contract could create a fake gap. BACKWARDS_RATIO already removes most of it; this is the conservative choice. |
| I-3 | **Stages A, B and B-EVE are computed in one run per instrument** (MODE 'ES', then 'NQ'), on identical days. Each stage is still computed exactly once. | Paired B − A needs the same days; it also halves the free-node runtime. |
| I-4 | **CFT-P is computed inside the QuantConnect run** (functions `overlay`, `combine_sim`, `green_month`, `cftp`). `cft_local.py` is not needed. | The free-tier log limit (≈ 10 KB) cannot export full trade lists. |
| I-5 | Only the **daily Stage B series** (integer bp) is logged (`NEXA_DAILY_B`), for a local descriptive DSR. | Log size. |
| I-6 | **F1 uses `tick.time` minutes as delivered.** These may be in exchange time (CT), shifting F1's window. That is harmless: F1 compares two classifiers on identical minutes. The second-bar emulation uses the last trade price and last quote in each second. | Classifier agreement only. |
| I-7 | ES / NQ runs start 2024-04-01 to warm up the 14 prior days. Only days ≥ 2024-05-10 enter the statistics. | Pre-registration §6 window. |
| I-8 | **Stop and band checks use the close of the bar ending at τ.** Entries and stop exits fill at the open of the bar starting at τ. A trade's R is the distance from entry to the stop level at τ. | As specified in PREREG §2; written out for the code. |
| D-1 | **F1 FAILED (2026-10-17, backtest "Calculating Tan Gorilla", 1ea437be…, ES 2024-01-02…05, 29.5 M ticks).**<br>- Result: 1,560 minutes; second-bar *quote* classifier vs tick-level classifier corr **0.717**, sign agreement **0.767** (< 0.80).<br>- **As pre-registered (§3), the gate now uses the declared fallback**: tick rule on the 1-s trade close (`FALLBACK = True`; the only code change besides MODE).<br>- `f1_report` now also reports the fallback's agreement on the same F1 days (diagnostic only; F1 is re-run in-sample, before any OOS day).<br>- **The fallback's quality is reported but does not change the plan**: Stage B uses it whatever its agreement. If it is weak, B is effectively a noisy filter, and that will show as B ≈ A or worse. | Pre-registered fallback path. |
| D-2 | **F1 reference defect found and fixed in-sample (2026-10-17, before any OOS day).**<br>- After D-1, a re-run of F1 (backtest "Sleepy Blue Butterfly", d0177a14…) gave **identical** quote and tick-rule numbers (corr 0.71672, sign 0.766667 for both). That is only possible if the stored bid/ask were always empty.<br>- **Cause:** `on_ticks` accepted a quote tick only when *both* bid and ask were above 0. AlgoSeek futures quote ticks update one side at a time, so no quote was ever stored. D-1's F1 therefore compared the 1-s tick rule against a tick-level **tick rule**, not against the pre-registered tick-level **quote rule**.<br>- **Fix** (main.py f504897d): bid and ask are updated separately; a quote-tick counter is added to the output. Nothing else changed.<br>- **Corrected F1** (backtest "Hipster Sky Blue Caribou", 29901d30…; ES 2024-01-02…05; 1,560 minutes):<br>&nbsp;&nbsp;- quote ticks 13,227,683 (bid > 0: 6,701,645; ask > 0: 6,526,038);<br>&nbsp;&nbsp;- 1-s quote classifier: corr **0.359**, sign agreement **0.663** (FAIL);<br>&nbsp;&nbsp;- 1-s tick-rule fallback: corr **0.683**, sign agreement **0.751** (also below 0.80; reported only).<br>- **Decision is unchanged from D-1:** §3 says that if F1 fails the gate uses the tick rule on the 1-s trade close, and `FALLBACK = True` stays.<br>- **Caveat for interpreting Stage B:** the gate's flow measure agrees with true aggressor flow only moderately (corr ≈ 0.68). A null B − A result may partly reflect measurement noise. | Bug in an in-sample diagnostic; the pre-declared decision path is unaffected. |
